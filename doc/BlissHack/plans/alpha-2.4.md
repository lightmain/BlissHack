# BlissHack alpha-2.4 规划入口

## 1. 文档状态

alpha-2.3 已于 2026-09-26 完成实现、自动门禁、独立复审和人工验收，根目录
`VERSION` 已切换为 `alpha-2.4`。

本文只建立 alpha-2.4 的规划入口和继承边界。产品目标、功能范围、实施阶段及
验收门禁尚未确认；完成需求讨论和计划评审前不得开始实现。

## 2. 继承基线

alpha-2.4 继承以下已完成能力：

- profile v4，以及 Detailed/Original 信息量、终局、角色创建和动作栏模式。
- BlissHack 动作栏、All Actions、布局编辑与 `.bhactions` 导入导出。
- 由核心真实输入驱动的物品、方向、位置、确认和普通单选次级流程。
- Original TTY 两行状态与 BlissHack 图形状态。
- Tiles/ASCII、永久背包、地图交互、本地存档、Ranking 和完整备份。
- 单元、WASM、Chromium、Firefox、WebKit、性能和长流程发布门禁。

## 3. 已确认边界

- 不把远程方向操作的射线高亮纳入 alpha-2.4。
- 现有方向输入继续显示可靠的八个邻格目标，不根据提示、动作名或物品名推断
  远程、射程、阻挡或反弹。
- 未经单独范围评审，不提升 profile、backup、command protocol 或 shim ABI
  版本。
- 候选需求、历史讨论和未完成想法都不是已确认的 alpha-2.4 交付项。

## 4. 规划步骤

1. 收集并归类 alpha-2.4 候选需求。
2. 选择一个边界清晰、可以独立验收的版本主题。
3. 阅读相关实现、测试、NetHack 核心调用链和既有设计文档。
4. 明确产品契约、兼容边界、非目标、风险和停止条件。
5. 设计分阶段实施顺序及每阶段测试门禁。
6. 完成计划评审并取得用户确认后，再进入实现阶段。

## 5. 开始条件

alpha-2.4 只有在以下条件满足后才开始实现：

1. 用户确认版本目标和非目标。
2. 关键交互已有文字契约；需要视觉验证时先完成原型。
3. 数据、存储、shim 和 NetHack 核心边界已经查明。
4. 测试策略明确区分默认值契约、固定场景测试和关键端到端流程。
5. 计划给出可验证的完成定义和人工验收清单。
