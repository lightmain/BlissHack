## 建议的实现结构

建议把后端分成下面几个职责明确的部分：

| 部分 | 职责 |
|---|---|
| 传输层 | TCP 监听、换行分隔 JSON、UTF-8、连接生命周期 |
| 会话层 | 握手、序号、`game.start`、错误处理 |
| 输入调度层 | 保存唯一活动提示，校验 `prompt_id`、输入类型和菜单项标识 |
| 核心适配接口 | 给测试核心和 NetHack 核心提供统一的输入、输出接口 |
| 测试核心 | 实现确定性的 0.1 验收流程 |
| NetHack 桥接层 | 连接 NetHack 窗口接口和核心适配接口 |
| Python 测试客户端 | 在 Godot 完成前执行协议和端到端验证 |
| Godot 客户端 | 保存后端完整快照、渲染界面、提交提示回答 |

推荐将通用后端代码放在 `godothack/godothack-server/`，NetHack 专用窗口接口放在 `win/godothack/`。这样可以减少对上游目录的分散修改。

## 每一步的固定停止规则

每个阶段结束时执行：

1. 只运行当前阶段最局部的测试。
2. 运行此前所有已经建立的自动测试。
3. 构建受影响的目标。
4. 执行 `git diff --check`。
5. 检查协议变更是否同步更新中英文协议、后端、Godot 和测试。
6. 当前阶段有失败时，只修复当前阶段，不提前开发下一阶段。

这套顺序把最容易造成返工的协议问题和 NetHack 回调问题提前暴露，同时让大前期绝大多数验证都能由 Python 完成。
