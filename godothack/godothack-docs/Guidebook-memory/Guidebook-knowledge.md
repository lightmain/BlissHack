## 输入命令模型

NetHack 的普通命令通常是一到两个按键，扩展命令通过 `#` 后接命令名执行。部分命令需要进一步输入方向、物品或位置；这时游戏会打开菜单，或在命令行提示玩家输入。`menustyle` 选项影响这些交互使用菜单还是传统提示。

常见提示会列出可选的库存字母。玩家按 `?` 可以先看候选物品列表，按 `*` 可以看完整背包，按 `Esc` 可以取消。部分命令允许在前面输入次数，例如 `10s` 表示搜索十次；启用 `number_pad` 后，次数前缀需要用 `n` 引入。

八方向移动使用 `yuhjklbn`，也支持数字键盘方向。大写方向键会沿方向移动到被阻挡或遇到事件。`m` 前缀用于移动时不拾取、不攻击记忆中的怪物，也可在一些命令中请求菜单。`F` 前缀用于强制攻击指定方向。`g`、`G` 或控制方向用于自动前进。`_` 是自动旅行到地图位置。

对 GodotHack 的输入层来说，后端仍然是命令解释的权威。前端应把鼠标点击、按钮和快捷键转换为后端命令，遇到后端发出的菜单或提示时，再用结构化 UI 呈现选择。

## 屏幕和地图查看

屏幕由顶部消息行、地图区域、底部状态栏组成。消息行负责表达无法直接画在地图上的事件；状态栏负责角色属性、生命、法力、防御、经验、回合、饥饿、负重和各种状态条件。

地图区域显示当前层已经探索或当前可见的信息。默认 ASCII 符号是一套显示约定：例如 `.` 可表示房间地面、冰、无门门洞或打开的吊桥；`#` 可表示走廊、铁栏、树或关闭吊桥的闸门；`+` 可表示关门或法术书；`@` 可表示玩家、人类或精灵；怪物多由字母或少数字符表示。这个表本身说明：同一个显示符号可能对应不同真实含义。

`#terrain` 和 `Del` 可以临时查看无遮挡地图。在普通游戏中，它允许查看已探索范围，并选择隐藏怪物、隐藏怪物和物品、隐藏怪物和物品和陷阱。这个命令对 GodotHack 很重要，因为它证明原版显示层有“遮挡”，同时也证明底层状态可以被用另一种显示模式重新组合。

## 菜单和提示

菜单和提示是 NetHack 交互的一部分，不只是终端实现细节。物品选择、选项设置、持久背包、层概览、拾取、容器操作都会用到菜单或命令行提示。

GodotHack 前端需要支持以下数据：

- 提示文本、默认答案、取消行为。
- 选择项列表、库存字母、物品描述、是否允许多选。
- 菜单分页或滚动，特别是持久背包显示。
- 命令是否消耗回合，以及是否只是查看信息。

## 物品、怪物和符号显示

怪物只在玩家可见或可感知时显示。看不见但被玩家察觉的怪物会用 `I` 表示“记忆中的、未见到的怪物位置”；通过 Warning 属性感知到的未见怪物可显示为 `1` 到 `5`。这些都是玩家知识层的显示，不等同于真实怪物类型和真实位置的完整公开。

物品可以在玩家离开视线后继续留在地图记忆中，但这个记忆可能过时。物品可能已经被怪物拿走或腐坏，直到玩家再次看见或触摸该格子才会更新。物品堆在显示层只显示最上面的物品；`hilite_pile` 只能让最上层物品用不同方式显示，不能让一个格子同时显示所有物品。

陷阱通常在被触发、被看见触发、搜索发现或魔法发现之前不会显示。秘密门和秘密走廊在发现前会伪装成普通墙或实心岩石。GodotHack 前端必须区分“真实状态”和“玩家已知状态”，否则会破坏 NetHack 的信息隐藏规则。

## glyph、显示信息和真实状态

Guidebook 用默认 ASCII 符号解释玩家能看到的结果；它没有定义 NetHack 源码里的 `glyph` 结构。对 GodotHack 来说，可以把后端发送给前端用于画格子的最终显示编号称为 `glyph`。`glyph` 适合快速复刻原版显示层，但不适合作为前端唯一的数据来源。

一个地图格子至少可能包含这些层：

- 地形或固定特征：地面、墙、门、水、岩浆、楼梯、祭坛、喷泉、商店边界等。
- 可发现但可能隐藏的内容：陷阱、秘密门、秘密走廊、刻字。
- 物品：没有物品、一个物品、一堆物品、金币、容器。
- 生物：玩家、怪物、宠物、坐骑、看不见怪物的记忆标记、Warning 数字。
- 玩家知识：当前可见、曾经见过、记忆可能过时、被遮挡、幻觉或失明影响。

显示层会按优先级选择一个符号给玩家看。例如一个怪物站在地面上时，显示层优先画怪物；一个物品堆在地面上时，显示层只画最上面的物品；一个未发现陷阱不会显示为陷阱。这些规则是原版界面的正常行为。

GodotHack 的地图消息建议至少包含这些数据层字段：地形类型、地形显示、可见性、探索状态、玩家记忆、陷阱信息、物品堆列表、最上层物品、怪物实体、显示用 `glyph`、以及该 `glyph` 是真实可见、感知、记忆还是临时视图生成的。前端可以默认按 `glyph` 绘制，再用结构化字段实现悬停说明、地面层绘制、物品堆面板和调试视图。

## 专门问题结论

### 原版 NetHack 玩家怎么查看地图上某个格子是什么东西？

主要用 `/` 命令，也就是 `whatis`。玩家可以指定一个符号，也可以把光标移动到地图上的某个格子，然后按 `.`, `,`, `;`, `:` 之一决定解释方式：`.` 会解释并可能询问是否显示更多信息，`,` 跳过更多信息但继续选点，`;` 跳过更多信息并结束选点，`:` 尽量直接显示更多信息。开启 `autodescribe` 后，光标移动时顶部消息行会显示短说明。`:` 命令用于查看自己脚下有什么，`;` 命令用于查看可见符号对应的类型。`#terrain` 可临时移除怪物、物品、陷阱等遮挡来查看已探索地图。

### 只把 glyph 输出给前端会不会丢失地砖或物品堆信息？

会，前提是这个 `glyph` 只是每格一个最终显示符号。原版 ASCII 显示层本来就会遮挡：生物站在某格上时，玩家看到的是生物符号，不是地砖符号；一个格子有多个物品时，玩家看到的是最上层物品，不能同时看到整堆物品；记忆中的物品也可能已经不在原处。这是显示层的取舍。

但这不代表 NetHack 的真实状态缺失。后端仍然知道地形、怪物、物品链、陷阱等真实状态，也知道哪些信息应该对玩家公开。GodotHack 前端如果只接收 `glyph`，就只能实现原版显示层；如果要稳定显示地砖、物品堆、悬停说明和分层图块，就需要后端额外发送数据层，并且按玩家知识规则过滤或标记这些数据。
